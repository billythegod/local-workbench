# 模块契约

本文档固化父服务器（workbench.py）与应用模块（apps/<name>/service.py）之间的全部约定，包括未成文的隐含约定。新增模块前先读完本文。

## 模块接口

```python
def api(method, path, query, body) -> tuple[int, dict|list]
```

- `method`：`"GET"` / `"POST"`（HEAD 已被父服务器转换为 GET）。
- `path`：`/api/<name>` 后的剩余部分，以 `/` 开头。**父服务器已对路径做过一次 `unquote`**，模块内不得再次解码（含 `%` 字面量的会话 key 会被二次解码损坏——历史 bug，已修复，勿重蹈）。
- `query`：`urllib.parse.parse_qs` 的返回形态 `dict[str, list[str]]`；键可能缺失，取值用 `query.get(key, [""])[0]` 并自行校验。
- `body`：POST 时保证是 `dict`（父服务器已校验 JSON 对象、≤2MB、深度/节点数预算），模块无需重复体积校验，但**必须**自行做字段类型与取值校验（好范本：runtime `check_preflight`、delivery `budgets`）。
- 返回 `(http_status, JSON 可序列化对象)`。父服务器用 `allow_nan=False` 序列化，NaN/Infinity 会降级为 500。

## 错误 → 状态码（统一映射，实现在 apps/_shared.py: api_error）

| 异常 | 状态码 | 说明 |
| --- | --- | --- |
| `FileNotFoundError` / `LookupError` | 404 | 资源不存在 |
| `ValueError`（含各模块 InputError）/ `TypeError` | 400 | 请求参数不合法 |
| `RuntimeError` | 409 | 冲突（如已有任务在跑） |
| `OSError` | 500 | 本地读写失败 |
| 其他（含 sqlite3.Error，history 自行前置处理） | 500 | 模块必须自己捕获映射；异常逃逸 `api()` 会被父服务器吞成通用 500（带堆栈进 data/server.log） |

路径已注册但方法不符 → 405（`_shared.not_allowed_or_missing(path, known_paths)`）；未注册 → 404。三个模块已对齐。

## 请求头约定（父服务器强制，模块无需检查）

- POST 必须带 `Content-Type: application/json` 与 `X-Workbench-Request: 1`；前端 fetch 封装统一负责。
- Host 精确匹配、Origin 白名单、`Sec-Fetch-Site: cross-site` 拒绝——DNS rebinding 与跨站 POST 在父服务器被拦。
- Handler 套接字超时 30 秒；请求体不完整（Content-Length 与实际字节不符）返回 400。

## 静态资源

- 模块界面：`apps/<name>/index.html`，浏览器访问 `/apps/<name>/`。
- 后缀白名单：`.html .css .js .svg .png .ico`；路径必须 resolve 后落在该模块目录内。
- 公共图标：`web/favicon.svg`，各页面以 `<link rel="icon" href="/favicon.svg">` 引用。

## 数据目录

- 模块只写 `data/<name>/`（可自建）；只读外部世界（历史库、进程表、扫描目录）。
- JSON 落盘一律用 `apps/_shared.py: write_json_atomic`（临时文件 + fsync + 原子替换，权限 0600）。
- 需要防删除/防篡改的凭据类数据（如 delivery 的快照与人工验收），追加写 `ledger.jsonl` 只追加登记簿，并提供登记簿↔磁盘双向比对的 `/audit` 端点。
- 时间戳一律 UTC ISO（`_shared.utc_now`）。

## 公共层（apps/_shared.py）

`redact(text, mode)`（full=入库正文；light=进程名/短输出）、`utc_now(timespec)`、`write_json_atomic`、`api_error(exc, scrub)`、`not_allowed_or_missing(path, known)`。新模块**不得**再复制这些实现；grep `def write_json|def utc_now|def scrub` 应只在 _shared.py 命中（模块内允许薄委托）。

## 导入方式兼容

service.py 需同时支持三种加载：父服务器 `importlib.import_module("apps.<name>.service")`、测试 `spec_from_file_location` 独立加载、CLI 直跑。统一写法：

```python
import sys
from pathlib import Path
if __package__ in (None, ""):
    sys.path.insert(0, str(Path(__file__).resolve().parents[2]))
from apps import _shared
```

## 新增一个模块的步骤

1. `apps/<name>/service.py`：实现 `api()`，用 `_shared` 公共层；尾部统一 `except Exception as exc: return _shared.api_error(exc, ...)`。
2. `workbench.py` 顶部 `APPS` 集合加名字（静态白名单是有意的安全属性：模块导入名永远不来自 URL）。
3. `apps/<name>/index.html`：界面可内联 CSS/JS；POST fetch 带两枚请求头；含加载/空/错误/重试四态。
4. `web/index.html`：侧栏导航、工具卡、titles 映射三处各加一条。
5. `apps/<name>/test_<name>.py` + `tests/<name>-browser.js`（browser 脚本是取证脚本，端口参数化，勿在 CI 断言）。
6. 模块 README：接口表、数据范围、边界声明（参考现有三个模块）。
