# 交付核验台

跨项目的文件证据工具。选定一个成品目录，登记文件清单、大小、修改时间、SHA-256 与有限的格式检查；保存快照、对比变化，并单独记录人工验收。它不调用项目自有 manifest/lineage 验证器，不替代这些业务约束。

## 使用

由根目录工作台服务器统一提供 `/apps/delivery/`，本模块不启动服务。界面可完成以下流程。

1. 填写成品目录的绝对路径，可逐行填写期望交付的相对文件路径。
2. 扫描并保存快照；查看覆盖统计、未完成哈希、具体问题及文件检查详情。
3. 修正文件后再次扫描，选择旧快照作为基准，查看新增、缺失、变化及无法确认的文件。
4. 实际打开成品完成人工查看后，填写查看范围和结论，勾选显式确认，保存人工验收记录。
5. 导出当前证据 JSON。该导出只包含文件证据、检查结果与人工记录，不含被扫描文件的正文。

打开旧快照和对比两个快照不会重新读取当前目录。扫描能使旧人工验收记录过期；文件清单、内容、修改时间或期望清单变化都会改变绑定的快照哈希。人工记录针对快照，不能证明记录之后目录持续未变。

## 检查与边界

| 格式 | 实际执行 | 未执行 |
|---|---|---|
| 所有普通文件 | 相对路径、大小、修改时间；预算内流式 SHA-256 | 内容语义与成品质量判断 |
| 媒体 | 本机 `ffprobe` 技术元数据：时长、视频分辨率、音轨数 | 正常速度观看、试听、画面与音质判断 |
| SRT / VTT | 基本时间格式、正向区间、时间顺序、重叠提醒；可关联媒体时检查时长上界 | 字幕语义、遮挡、完整标准语法校验 |
| JSON | UTF-8 JSON 语法解析；拒绝 NaN/Infinity | 业务 schema 与事实正确性 |
| DOCX / XLSX / PPTX 及宏格式 | ZIP 容器、必要成员、危险/重复路径、加密成员；有限预算内读取 CRC | 原生 Office 渲染、XML 完整业务语义、公式重算、宏执行、排版或内容验收 |
| 旧版 DOC / XLS / PPT | 文件登记及预算内哈希 | 二进制结构检查 |
| Markdown | 基本 inline 链接和引用定义中的目录内相对目标存在性，排除代码围栏 | 外部 URL 请求、锚点及复杂 Markdown 解析 |
| PDF | 文件头及尾部 EOF 标记 | 页面解析、字体、排版、渲染 |
| HTML、图片、CSV、其他格式 | 文件登记及预算内哈希 | 页面运行、脚本执行、渲染及数据语义 |

字幕优先关联同目录同名媒体；没有同名媒体且目录仅一份媒体时使用该媒体。无法唯一关联或时长未知时，上界检查显示未执行。上界容差为 0.15 秒。

自动层级“已执行通过”仅表示本次实际执行的技术检查未发现问题。原生渲染始终记录为未运行。没有任何操作会自动写入人工通过、发布成功或将文件移动到 `final`。

## 只读范围与预算

- 所选目录只读；输出固定写入 `data/delivery/manifests/` 和 `data/delivery/acceptances/`。
- 隐藏项、凭据/密钥/令牌等敏感文件名、`node_modules`、虚拟环境、依赖目录、会话库与所有符号链接跳过。扫描入口拒绝宽泛的系统/用户根目录与敏感路径。
- 普通文件通过根目录 fd 逐级打开，目录和文件不跟随符号链接；不解压文件到磁盘，不执行被扫描代码，不请求外部链接，不读取凭据内容。
- 默认最多 1500 个文件、6000 个目录项、深度 10、20 秒；超出范围明确记录覆盖不完整。
- 默认哈希单文件 32 MiB、总计 128 MiB，按块读取。显式选择大文件哈希后，单文件最多 4 GiB、总计 8 GiB，仍受最多 45 秒约束。
- 默认单个文本最多 2 MiB；结构检查总读取 64 MiB；单个 Office 解压读取最多 64 MiB。成员最多 10000；Office 容器本身超过结构预算时不会打开。未完成检查明确记录，不以文件存在代替通过。
- 被排除项属于声明的扫描范围外；“清单覆盖完整”指排除规则内的范围。跳过记录最多展示 200 项，统计保留实际数量。
- 文件哈希绑定路径、大小、修改时间、SHA-256、期望清单和清单覆盖；另存证据哈希防止检查结果意外损坏。二者不构成数字签名或外部认证。
- 仅清单覆盖完整且所有文件哈希完成时允许人工验收记录；接口还要求显式确认与非空查看说明。自动检查有错误时，人工记录仍然独立显示，不会清除错误。

## 模块接口

`service.py` 导出 `api(method, path, query, body) -> (http_status, dict)`。`path` 是 `/api/delivery` 后缀；`query` 是 `parse_qs` 形式。

| 方法与路径 | 输入 | 输出 |
|---|---|---|
| `GET /config` 或 `/` | 无 | 默认/最大预算、检查边界、本机 ffprobe 可用性与示例目录（未配置时为 null） |
| `GET /manifests` | 无 | 最近 100 个快照摘要 |
| `GET /manifest` | `?id=快照编号` | 完整快照及该目录最新人工记录是否与此快照匹配 |
| `POST /scan` | `directory`，可选 `expected`（字符串逐行或路径数组）、`budgets` 对象 | 完整扫描结果；自动保存快照 |
| `POST /compare` | `baseline_id`、`current_id` | 同目录快照的新增、缺失、变化、修改时间变化、无法确认、一致、期望清单差异 |
| `POST /accept` | `manifest_id`、`manifest_hash`、`decision` 为 `accepted/rejected`、`acknowledgment: true`、`note` | 绑定快照的显式人工记录 |

所有 POST fetch 使用 `Content-Type: application/json` 与 `X-Workbench-Request: 1`，由父服务器检查来源。本模块不提供后台服务入口。

预算键为 `max_files`、`max_entries`、`max_depth`、`seconds`、`hash_total_mb`、`hash_file_mb`、`text_file_mb`、`check_total_mb`、`office_uncompressed_mb`。单位 MiB；`/config` 返回最大值。非法路径、越界期望清单、非法快照 ID 和损坏快照返回 400；本地存储失败返回 500。

## CLI

```sh
python3 apps/delivery/service.py scan /绝对路径/out --expected 成片.mp4 --expected 成片.srt
python3 apps/delivery/service.py check /绝对路径/out --no-save
python3 apps/delivery/service.py scan /绝对路径/out --large-hash --seconds 45
python3 apps/delivery/service.py compare 基准快照编号 当前快照编号
python3 apps/delivery/test_delivery.py
```

`scan` 默认保存到工作台数据目录，`--no-save` 只输出 JSON；`check` 始终不保存。`compare` 读取工作台已有快照。标准输出为 JSON，不创建压缩包。

| 退出码 | 含义 |
|---|---|
| 0 | 本次实际执行的检查无错误或提醒；对比覆盖完整且没有文件/期望清单差异 |
| 1 | 检查发现错误；或对比发现新增、缺失、文件变化、修改时间变化、期望清单变化 |
| 2 | 输入、路径、存储或执行错误 |
| 3 | 没有硬错误，但覆盖、哈希或检查未完成，或存在需要人工判断的提醒 |

CLI 的 0 不代表人工验收、原生渲染、平台接受或发布成功。

## 已执行验证

合约测试见 `test_delivery.py`（`python3 -m unittest discover -s apps/delivery -p 'test_delivery.py' -v`），覆盖：文件缺失/变化、人工记录不能自动通过与变化过期、快照自比拒绝、登记簿缺失与篡改检测、伪哈希快照拒绝、字幕非法及越界、真实 WAV 元数据、Office 缺必要成员/危险路径/损坏容器、路径逃逸、敏感项/符号链接跳过、哈希预算与无法确认、覆盖不完整、证据损坏和 CLI 退出码。测试只在临时目录构造样本，不读取真实成品。

浏览器自动验证与截图检查不能替代人的成品验收；没有任何操作会通过浏览器自动写入人工 accepted 记录。
